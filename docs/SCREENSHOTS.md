# Interface screenshots

`bubble-navigation.png` is a real Chromium capture of the counters, filters,
breadcrumb path and 15-row legend. `packaging/check_bubble_labels_ui.py`
generates 127 invented records across 21 artist groups, including long,
multilingual and deliberately HTML-like names used to check safe rendering.
These are temporary test records; no catalogue or audio is distributed.
The screenshot was reviewed using a clean disposable server and the same
mouse/keyboard, scroll, SVG-area and source-preservation acceptance checks.

`workflow-map.png`, `library-preparation.png` and `media-inventory.png` are
generated by `packaging/check_preparation_inventory_ui.py` through the existing
Chromium/Firefox/WebKit browser checks. They use real HTTP/SQLite operations,
a generated two-track native database/XML+ZIP pair and one 100-byte silent WAV.
The fixture is generated during testing; its databases, backups and audio are
not shipped. These captures document the landing map, explicit preparation
choice and workspace-scoped inventory. No personal cloud paths or music are used.

The first three README PNG images are browser captures from GitHub Actions, generated by `packaging/check_enrichment_ui.py` through `packaging/check_browser_languages.py`. They use the application UI with a temporary synthetic snapshot. The two additional WebP images (`musicbrainz-enrichment-real.webp` and `library-bubbles-real.webp`) are user-provided screenshots of an actual library. They have been resized and compressed for documentation, not generated from test fixtures; visible song titles and library counts are authentic to that example.

## Original three synthetic PNG captures: data and size

- Exactly 12 invented records named Test Track and Test Artist, including Unicode and version suffixes.
- Two test playlists and two saved sessions, sufficient to show playlist overlap, repeated history and local playback availability.
- Approximately 10 KB of serialized metadata (9,848 bytes in the initial GitHub capture; temporary path lengths can affect the exact size).
- One generated 0.1-second mono silent WAV, 1,644 bytes, used only to exercise file availability.
- No copied artist catalogue, commercial recording, personal library or source database.
- The original three synthetic PNG screenshots total 707,826 bytes (approximately 0.71 MB). The two user-supplied WebP screenshots are visual documentation only; no music or database files are included.
- Zero catalogue records and zero audio bytes bundled as application demo data. Source archives include generator code; screenshots contain rendered invented metadata.
- Release verification rejects audio files and recognized rekordbox/Serato database payloads.

The screenshot fixture was reduced from 48 to 12 records. Larger performance and format tests generate their own synthetic records only while running; reducing those would weaken large-library checks without reducing distributed music data.

## Dropbox metadata connector

`dropbox-setup.png` and `dropbox-confirmation.png` are reviewed Chromium captures
from `packaging/check_dropbox_connector_ui.py`. The first shows connection setup,
the exact local OAuth redirect URL and an explicit local-to-remote folder mapping.
The second shows the warning, track name, destination path, size and Cancel option
before one file can be downloaded.

The browser uses real application HTTP routes and temporary SQLite storage. A
synthetic server-side Dropbox transport supplies an invented account, public app
key, team/customer folder names and 61 invented remote file entries; two further
library records exercise absent and unmapped paths. No browser API responses are
intercepted. No external Dropbox service or actual cloud account is contacted,
and these captures do not establish live-account compatibility. OAuth and
credential-store behavior have separate automated tests.

The confirmed download creates one short non-audio test payload in a temporary
folder. Cancel and Escape create no file; metadata checks download no content.
No actual music, personal paths, credentials or library database is packaged.
Only the rendered PNG screenshots and test-generator code are included in source
archives; the temporary metadata, provider inventory and payload are discarded.

Regenerate the evidence with:

```sh
python packaging/check_dropbox_connector_ui.py --browser chromium --output ci-output/dropbox-connector
```

Review `dropbox-setup.png` and `dropbox-confirmation.png` before copying them to
`docs/screenshots/`. Keep the invented account and metadata labels visible.
