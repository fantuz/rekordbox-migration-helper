# Interface screenshots

The **first three README images** are browser captures from GitHub Actions, generated by `packaging/check_enrichment_ui.py` through `packaging/check_browser_languages.py`. They use the application UI with a temporary synthetic snapshot.

Two further user-provided captures (`musicbrainz-enrichment-real.webp` and `library-bubbles-real.webp`) show an actual personal DJ library. The owner explicitly requested adding these images to the README. Their visible library names and counts are not synthetic test data. These images have been resized and WebP compressed for repository size; their content has not been replaced with a fictitious library. No audio, source database or library snapshot is included.

## Data and size

- Exactly 12 invented records named Test Track and Test Artist, including Unicode and version suffixes.
- Two test playlists and two saved sessions, sufficient to show playlist overlap, repeated history and local playback availability.
- Approximately 10 KB of serialized metadata (9,848 bytes in the initial GitHub capture; temporary path lengths can affect the exact size).
- One generated 0.1-second mono silent WAV, 1,644 bytes, used only to exercise file availability.
- No copied artist catalogue, commercial recording, personal library or source database.
- The original three synthetic fixture PNG screenshots total 707,826 bytes (approximately 0.71 MB). The two separately supplied real-library WebP screenshots add approximately 76 KB of compressed image assets.
- Zero catalogue records and zero audio bytes bundled as application demo data. Source archives include generator code; screenshots contain rendered invented metadata.
- Release verification rejects audio files and recognized rekordbox/Serato database payloads.

The screenshot fixture was reduced from 48 to 12 records. Larger performance and format tests generate their own synthetic records only while running; reducing those would weaken large-library checks without reducing distributed music data.

## Regeneration

Run the **Check and package** GitHub workflow on the proposed change. Its browser job executes:

```sh
python packaging/check_browser_languages.py --browser chromium --output ci-output/languages
```

Download the `language-validation-chromium` artifact and review these three files before committing them under `docs/screenshots/`:

- `readme-library-insights.png`
- `readme-track-editor.png`
- `readme-playlist-explorer.png`

Keep synthetic labels visible. Update the README captions and this description if fixture size or contents change. Never replace them with a personal library capture.
