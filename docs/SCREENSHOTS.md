## Original three synthetic PNG captures: data and size

- Exactly 12 invented records named Test Track and Test Artist, including Unicode and version suffixes.
- Two test playlists and two saved sessions, sufficient to show playlist overlap, repeated history and local playback availability.
- Approximately 10 KB of serialized metadata (9,848 bytes in the initial GitHub capture; temporary path lengths can affect the exact size).
- One generated 0.1-second mono silent WAV, 1,644 bytes, used only to exercise file availability.
- No copied artist catalogue, commercial recording, personal library or source database.
- The original three synthetic PNG screenshots total 707,826 bytes (approximately 0.71 MB). The two user-supplied WebP screenshots are visual documentation only; no music or database files are included.
- Zero catalogue records and zero audio bytes bundled as application demo data. Source archives include generator code; screenshots contain rendered invented metadata.
- Release verification rejects audio files and recognized rekordbox/Serato database payloads.

The screenshot fixture was reduced from 48 to 12 records. Larger performance and format tests generate their own synthetic records only while running; reducing those would weaken large-library checks without reducing distributed music data.

## Dropbox metadata connector

`dropbox-setup.png`, `dropbox-confirmation.png` and
`dropbox-play-confirmation.png` are reviewed Chromium captures
from `packaging/check_dropbox_connector_ui.py`. The first shows connection setup,
the exact local OAuth redirect URL and an explicit local-to-remote folder mapping.
The second shows the warning, track name, destination path, size comparison and
Cancel option before one file can be downloaded. The third shows the separate
consent to download and then open one reachable track, including a deliberately
different captured library size.

The browser uses real application HTTP routes and temporary SQLite storage. A
synthetic server-side Dropbox transport supplies an invented account, public app
key, team/customer folder names and 61 invented remote file entries; two further
library records exercise absent and unmapped paths. No browser API responses are
intercepted. No external Dropbox service or actual cloud account is contacted,
and these captures do not establish live-account compatibility. OAuth and
credential-store behavior have separate automated tests.

The confirmed actions create two short non-audio test payloads in a temporary
folder. Download-only consent does not open a player. The Play regression waits
for the verified local file before calling a stand-in for OS dispatch; no real
audio player runs. Cancel and Escape create no file; metadata checks download no content.
No actual music, personal paths, credentials or library database is packaged.
Only the rendered PNG screenshots and test-generator code are included in source
archives; the temporary metadata, provider inventory and payload are discarded.

Regenerate the evidence with:

## Guided cloud connections and separate file evidence

`cloud-connection-setup.png`, `cloud-attachment-preview.png` and
`cloud-file-evidence.png` are reviewed Chromium captures generated by
`packaging/check_cloud_connections_ui.py`. They show the exact OAuth callback
before authorization, the library-path preview before attaching a selected-file
cache, and local access beside the separately checked cloud presence.

The harness runs the real application HTTP routes, JavaScript, SQLite store,
background jobs and filesystem operations. Only the remote Dropbox/Google Drive
transports and local provider discovery fixture are synthetic. The collection
has 64 invented records: two Dropbox references, 61 Google Drive references and
one unmapped reference. Its provider account names, paths and metadata are
invented. No application API responses are intercepted and no live cloud
account is contacted.

File health is explicitly scanned, then paired with cached provider metadata
for the same source. A cloud-present Dropbox file remains locally Unknown until
local evidence establishes availability. A different collection with the same
track IDs cannot inherit that cloud evidence. Opening File health does not
query either remote provider. One confirmed Google Drive transfer creates a
short non-audio payload; cancellation and a rejected corrupt transfer leave no
additional local file. The temporary snapshots, provider inventory and payload
are discarded and are not included in packages.

`release-year-order.png` uses a separate seven-record invented snapshot. The
browser checks newest-year ordering, track-count ordering, preservation of the
unknown filter and unchanged chart totals. Changing order does not request the
statistics API again. This screenshot contains rendered metadata only.
